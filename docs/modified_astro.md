# Модифицированные астроциты: модели и MDP-конфиги

Этот документ описывает текущий код ветки `modified_astro`. Исторические итоговые PDF добавлены в `reports/`: [каталог и ограничения интерпретации](experiment_reports.md). Веса и сырые истории не перенесены. Исторический четырёхкартовый протокол статьи сохранён отдельно и запускается явно с `--legacy`.

## Модель и граница наблюдений

```text
среда → RBF64 [и availability4 для трёх целей]
                       ↓
                  RSNN100:50LIF+50ALIF
                       ├─ реальная активность → запись памяти
                       ├─ H(z, действие) → прогноз следующей RSNN100 → чтение памяти
                       └─ detached признаки → моторная голова
память → территориальная familiarity → локальные gates/gains →4/20I →4 Motor LIF
```

`representation()` актуальных астроцитарных моделей принимает готовые RBF-признаки, а не координаты. Карты, shortest paths и метки посещённости доступны только окружению/оценщику. Прогнозы не записываются в память и не выполняют виртуальный RSNN-шаг. Достигнутая активность наблюдается один раз, сохраняется как `next_z` и переиспользуется как исходное состояние следующего действия. После сбора контрольной точки target включает новое состояние availability.

Предиктор104→128→128→100 обучается единственному MSE следующей реальной активности с фиксированным масштабом начальной калибровки. Target detached. RSNN получает только prediction e-prop; RL обновляет моторные веса и управляющие памятью усиления. Replay обновляет только предиктор. `horizon` задаёт согласованную нормировку advantage для моторной головы и путей:50 в одноцелевом MDP,150 в three-goal.

Время RSNN —1ms,128 внутренних шагов на наблюдение. В пуле и его single-контроле моторный/ингибирующий шаг1ms, окно180ms. У более раннего адаптивного смешивания сохранён исходный шаг3ms и60 отсчётов. Это разные протоколы дискретизации, явно отражённые в `motors/`.

## Варианты без дублирования моделей

`PopulationLearner` реализует одной параметризуемой моделью:

| Поле | Значения и смысл |
|---|---|
| `memory.cells` | число территорий; для сохранённых factorial-профилей5 |
| `memory.connectivity` | `local`: локальные группы; `full`: весь RSNN каждому астроциту |
| `memory.overlap` | степень покрытия нейрона территориями при локальном входе |
| `memory.heterogeneous`, `tau_span` | одинаковые tau или геометрический разброс с тем же геометрическим центром |
| `motor.aggregation` | `pool`: один I на astro×action; `single`: один I на действие после усреднения |
| `motor.learn_paths` | обучать локальные усиления или фиксировать их равными1 |
| `motor.reliability` | включать калибровку уверенности прогнозов |

Пять локальных территорий по20 дают100 кальциевых процессов. При полном входе пять территорий по100 дают500 процессов. У каждой пары astro×action свой ограниченный gain `0.25+1.75*sigmoid(theta)`, начально1. При20I каждая клетка выполняет LIF-нелинейность до усреднения проводимостей. При4I сначала усредняется evidence×gain, затем работает одна клетка на действие. Нормировка и cap тока совпадают; это проверяется тестом равных территориальных входов.

Полный вход нормирует reliability mass к тому же числу каналов, что локальная территория: при пяти клетках применяется множитель0.2. Запись/забывание кальция имеют независимые времена. Внутри каждого процесса сохраняются glutamate, calcium и velocity; здесь нет списка наблюдений.

`AdaptiveAstroLearner` — отдельный ранее проверенный механизм: пять глобальных softmax-весов смешивают familiarity до общей4I-головы. Он отличается от20 локальных усилений математикой RL-кредита и моторным интегратором, поэтому не маскируется простым флагом пула. Число клеток и перекрытие остаются параметрами `population`.

Актуальные No Astro/AstroRL/Trace используют такой же прямой прогноз RSNN100. AstroRL сохраняет исходную одношкальную кальциевую динамику, Trace использует настоящую EMA активности. У No Astro память отключена; общий моторный scaffold содержит4 неактивных при нулевом gate ингибиторных канала. Эти новые контрольные профили не выдаются за побитовое повторение более ранних baseline с RBF-target.

## Familiarity и причинный порядок

Единая `rsnn_activity_code()` применяется и к реальным записям, и к прогнозам:

- `excess`: вычитание фиксированного начального фона, масштабирование, clip0..3 и деление на3;
- `rate`: прежняя положительная rate-нормировка;
- `signed`: знаковые стандартизованные отклонения, делённые на sqrt(neurons), для Whole/RFF.

Фон сохраняется фиксированным для воспроизведения MDP-серий. Это не EMA фона; EMA — самостоятельный Trace-backend. Принудительное разреживание RSNN не добавлено.

Backends находятся в `population_memory.py` и `dense_memory.py`:

- `astro`: исходный кальций с одним tau, но уже на активности RSNN;
- `calcium`: территориальные процессы с независимыми write/forget tau;
- `trace`: EMA-следы активности;
- `whole`: максимум RBF-сходства с целыми записанными векторами;
- `rff`: затухающий след случайных нелинейных признаков, приближающий среднее RBF-сходство;
- `none`: отсутствие памяти.

Whole и RFF совместимы с плотными кодами, но имеют разные правила агрегации (max/mean) и бюджеты. Они заменяют запись и чтение, не просто формулу скалярного произведения. Это альтернативы кальциевой памяти, а не биофизические астроциты. Одна общая familiarity повторяется на пять моторных путей; это не пять независимых хранилищ. В метаданных у них0 астроцитов.

На каждом переходе: прогнозное чтение → реальное действие → наблюдение реального `next_z` → чтение real familiarity из **той же pre-write памяти** → обновление локальной reliability → запись real activity. Версия памяти защищает этот порядок. Начальное состояние записывается до первого действия, терминальное — один раз. Evaluation сбрасывает динамику и не меняет глобальные веса, baseline, ошибки/счётчики reliability.

## Составные конфиги

Все ссылки задаются относительно `configs/`; JSON поддерживает `extends` с рекурсивным объединением объектов. Неизвестные пути, выход за `configs/` и циклы отклоняются. Верхнеуровневый файл содержит ссылки и выбор условий:

```json
{
  "name": "mdp_three_goal_factorial",
  "environment": "environments/mdp_three_goal.json",
  "map_set": "maps/checkpoints.json",
  "models": {
    "full_mixed_pool": {
      "extends": "models/full_mixed_pool.json",
      "architecture": "architectures/rsnn100_context.json"
    }
  },
  "protocol": "protocols/mdp_three_goal.json"
}
```

Полный поставляемый конфиг содержит все четыре варианта. `models/` связывает архитектуру, память, мотор и выбранные параметры; `parameters/` содержит только идентификаторы условий и hp, без метрик результатов. `parameter_match` выбирает семейство/вариант/группу, `parameter_overrides` явно переопределяет hp. Архитектурные поля, например cells/connectivity, изменяются в `memory`/`population`, а не через неиспользуемые поля hp.

### Сохранённые MDP-серии

| Конфиг в `configs/experiments/` | Объём и параметры |
|---|---|
| `mdp_pool.json` | 2 варианта tau × RL/no-RL ×60 карт ×3 seed =720 обучений;250эпизодов,50шагов,100evaluation |
| `mdp_adaptive.json` | адаптивное смешивание, тот же720-run дизайн и собственные выбранные hp |
| `mdp_factorial.json` | full/local ×20/4I ×ordered/unordered ×60 карт ×3seed =1440;300эпизодов,150шагов,100evaluation |
| `mdp_controls.json` | новые RSNN-activity No Astro/AstroRL/Trace/Random и исторические Q-table/Q-RNN; явные профили параметров |
| `mdp_dense.json` | MDP-абляция Local20I/Whole/RFF; подготовленный протокол, не сохранённый численный MDP-результат |
| `smoke_*.json` | явные укороченные проверки исполнения:branching,1 карта,1seed,2эпизода,1evaluation |

В основных сериях по20 финальных карт obstacles/rooms/branching; шесть прежних tune-карт также сохранены. Seed72000..72002, исходные старты, геометрии и точки не меняются. В three-goal — fixed start, reward+1 однократно за каждую из3 целей, без step penalty; normalized reward=collected/3. В single-goal — IID non-goal старты, reward=success−0.01T и прежняя min–max нормировка.

Калибровка three-goal сохранена по маскам availability1..15, как в исходной серии; в реальных наблюдениях три бита целей и нулевой четвёртый. Full/mixed и local/equal одновременно меняют покрытие, tau и ёмкость памяти: это не чистое выделение эффекта локальности. В factorial-серии hp общие для четырёх вариантов в каждом семействе, взяты из homogeneous/RL single-goal пула. Отдельный подбор здесь не выполняется.

### Запуск

```bash
uv sync --frozen
uv run python -m experiments plan --config experiments/mdp_factorial.json
uv run python -m experiments run --config experiments/smoke_factorial.json --workers 2 --output results/smoke-factorial
uv run python -m experiments plot --config experiments/smoke_factorial.json --output results/smoke-factorial
```

Для полной серии выберите `mdp_factorial.json`/`mdp_pool.json`/`mdp_adaptive.json`. Длительные запуски выполняются на вычислительном сервере; число процессов берётся из protocol.workers либо `--workers`. CLI ограничивает его30. Здесь такие серии заново не запускались.

Evaluation factorial:learned,uniform,off,confidence_off,background_off,pooled_control. В dense-контроле background_off не используется: он не определён для знаковых kernel-признаков. Uniform и OFF — inference-абляции одних обученных весов, не независимые обучения.

Manifest фиксирует resolved config, hashes конфигов/исходников, Python/NumPy/PyTorch. Завершённые задачи пропускаются; прерванная задача повторяется целиком. Изменённый конфиг/код/окружение требует другого output. Истории сохраняются сжатым JSON, навигация — uint8 actions с offsets и occupancy. Сырые результаты в Git не добавляются; запрошенные исторические итоговые PDF находятся в `reports/`.

Сохранены проверки конечности параметров, обновления RSNN/предиктора, замороженных policy-весов без RL и отсутствия коллапса на независимом фиксированном probe. Их пороги явно указаны в `protocol.validation`.

`plot` экспортирует reward01, coverage, path efficiency, AUC несглаженных training-кривых и графики PNG/PDF/SVG. AUC — трапеции/(N−1), не AUROC посещённости. Bootstrap сначала ресемплирует карты, затем seed внутри карты; для factorial сохраняются парные эффекты20I−4I и interaction. Незавершённая выборка не агрегируется как завершённая. Smoke-интервалы одной карты/seed не являются оценкой обобщения.
